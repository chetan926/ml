### 2.5 Zero-Overlap Positive Text Pairs Audit

A critical challenge identified in Contribution 1 is candidate generation failure when paraphrased plagiarized pairs share zero lexical word overlap.
* **Empirical Count:** Across `snli_val`, exactly **119 positive candidate pairs** ($y=1$) exhibit a token-level Jaccard similarity of exactly $0.0$.
* **Lexical Filter Failure:** A pure BM25 or word-overlap filter with threshold $\tau > 0$ misses 100% of these 119 true positive pairs (candidate recall drops by $\sim 9.0\%$ on the positive slice).
* **Multi-View Semantic Recovery:** By coupling character-level n-gram hashing with MiniLM-L6-v2 dense semantic cosine similarity, the proposed multi-view candidate generator recovers these zero-overlap pairs, maintaining $R_{\text{target}} \ge 0.98$.

### 3.4 Structural Impossibility Proof: Degeneracy of 5-Fold Platt Scaling on `case-05`

Previous Phase 2 proposals suggested evaluating `case-05` using 5-fold cross-fitting Platt scaling to obtain calibrated probabilities. The following empirical analysis provides formal mathematical proof that **5-fold cross-fitting Platt scaling on `case-05` is structurally degenerate and impossible**:

#### Empirical Composition of `case-05`:
1. `case-05` consists of 58 `.java` source files comprising:
   - Exactly **one (1) original reference implementation**: `original/Main.java`.
   - Exactly **15 independent non-plagiarized implementations**: `non-plag-01` through `non-plag-15`.
   - Exactly **42 plagiarized variants**: obfuscated versions of `original/Main.java` (identifier renaming, statement reordering, dead-code insertion).
2. The dataset contains 107 evaluated pairs:
   - **54 non-plagiarized pairs ($y=0$):** Comparisons between `original` and non-plagiarized files, or between different non-plagiarized files.
   - **53 plagiarized pairs ($y=1$):** Every single positive pair in `case-05` is a direct comparison involving `original/Main.java`.

#### Fold Allocation Across 16 Base Program Identities:
Under group-level partitioning (grouping by program identity to prevent identical source code from leaking across training and validation), the 16 base program identities (1 original + 15 non-plagiarized) must be distributed across 5 folds:

| Fold # | Assigned Base Programs | Positive Pairs in Training ($N_{\text{pos}}^{\text{train}}$) | Negative Pairs in Training ($N_{\text{neg}}^{\text{train}}$) | Held-Out Test Positives ($N_{\text{pos}}^{\text{test}}$) | Held-Out Test Negatives ($N_{\text{neg}}^{\text{test}}$) | Platt Logistic Regression Solver Status |
| :---: | :--- | :---: | :---: | :---: | :---: | :--- |
| **Fold 1** | Holds out `original/Main.java` + 2 non-plag | **0** | ~43 | **53** | ~11 | **DIVERGES TO $-\infty$ (Zero Positive Class)** |
| **Fold 2** | Holds out 3 non-plagiarized programs | 53 | ~43 | **0** | ~11 | ROC-AUC / ECE Undefined (Zero Test Positives) |
| **Fold 3** | Holds out 3 non-plagiarized programs | 53 | ~43 | **0** | ~11 | ROC-AUC / ECE Undefined (Zero Test Positives) |
| **Fold 4** | Holds out 3 non-plagiarized programs | 53 | ~43 | **0** | ~11 | ROC-AUC / ECE Undefined (Zero Test Positives) |
| **Fold 5** | Holds out 4 non-plagiarized programs | 53 | ~43 | **0** | ~11 | ROC-AUC / ECE Undefined (Zero Test Positives) |

#### Mathematical Proof of Failure:
In Fold 1, because `original/Main.java` is held out, the training fold contains $N_{\text{pos}}^{\text{train}} = 0$ positive pairs ($y=1$ never occurs). The negative log-likelihood objective of logistic regression (Platt scaling) simplifies to:
$$\mathcal{L}(A, B) = \sum_{i=1}^{N^{\text{train}}} \log(1 + \exp(A z_i + B))$$
Because $y_i = 0$ for all training instances, the loss is strictly monotonically decreasing as $B \to -\infty$ (or $A \to -\infty$ for positive margins). Standard gradient descent, L-BFGS, or Newton-Raphson solvers diverge, producing overflow warnings or degenerate infinite coefficients.

In Folds 2 through 5, the training set contains all 53 positive pairs, but the held-out test fold contains **zero positive pairs** ($N_{\text{pos}}^{\text{test}} = 0$). Consequently:
- Precision, Recall, and F1 are mathematically undefined ($0/0$).
- ROC-AUC is mathematically undefined because the true positive rate cannot be calculated.
- Expected Calibration Error (ECE) is meaningless because no calibration against positive events can be validated.

#### Methodological Conclusion and Protocol Modification:
This empirical proof definitively refutes the feasibility of 5-fold cross-fitting Platt scaling on `case-05`. As mandated in Version 3.3:
1. Forced cross-fitting Platt scaling on `case-05` is completely rejected.
2. The IR-Plag code benchmark is evaluated strictly using **exploratory raw decision margin thresholding** $z(\mathbf{x})$.
3. Conformal coverage guarantees and calibrated probability metrics are **formally disclaimed for source code**.
4. Tasks `case-06` ($N=199$) and `case-07` ($N=199$) are reported as completely independent test sets, avoiding invalid pooling across distinct program domains.
